# 第一阶段 MVP 范围

## 1. MVP 成功标准

第一阶段成功不是“页面都能打开”，而是一个真实用户能够在安全、可追踪、可计费的前提下完成：

```text
注册/登录
→ 获得试用额度
→ 创建招聘任务
→ 生成并确认 JD
→ 上传或选择简历
→ 确认筛选方案与预算
→ 查看解释性筛选结果
→ 选择候选人并生成面试题
→ 回看任务和消费流水
```

## 2. P0 用户

### 2.1 组织管理员

- 注册并创建组织。
- 查看组织余额和消费流水。
- 使用所有 P0 招聘能力。
- 管理个人资料和基础组织信息。

### 2.2 招聘人员

第一阶段可与管理员为同一个账号类型。数据模型预留成员关系，但完整邀请、顾问、只读角色进入 P1。

## 3. P0 功能范围

### 3.1 登录与初始化

- 手机验证码登录/注册。
- 用户协议、隐私政策确认。
- 新用户可选的企业名称、角色、规模、行业信息采集。
- 创建默认组织并发放试用额度。
- 进入产品后的简要三步引导。
- 登录态过期、网络错误和重复提交处理。

不包含：微信登录、密码登录、复杂设备管理。

### 3.2 全局框架与概览

- Top Navigation：产品名、总可用余额、计费说明、用户菜单。
- Sidebar：概览、智能招聘、职位库、人才库、充值/账单、设置。
- 概览：职位数、候选人数、近期 AI 任务、今日/本月消耗、待人工确认事项。
- 余额不足和异常任务提醒。

面试题库 P0 不作为完整一级管理模块；面试题结果从招聘任务、职位和候选人详情进入。

### 3.3 智能招聘工作台

- 创建和恢复招聘任务。
- 左侧结构化成果区，右侧可收起 AI 助手区。
- AI 能力入口：JD 生成、简历筛选、AI 面试出题。
- 会话消息、流式生成、任务进度和费用展示。
- 最近任务回看和继续处理。
- 刷新页面或网络恢复后重新获取服务端任务状态。

完整 AI 招聘自动工作流进入 P1。P0 使用“完成一步后建议下一步”的引导式串联。

### 3.4 JD 生成与职位库

- 对话采集岗位名称、职责、要求、地点、薪资、用工性质、背景和团队痛点。
- 支持粘贴原始招聘需求。
- 输出结构化 JD 草稿和人才画像。
- 用户编辑、确认和保存。
- 确认后创建不可变 JD 版本；后续编辑创建新版本。
- 职位列表、关键词/结构化筛选、详情、草稿、归档。
- 查看关联筛选记录和面试题结果。

P0 不包含职位发布到外部渠道。

### 3.5 简历导入、解析与人才库

- 支持 PDF、DOC、DOCX；具体大小和批量上限待确认。
- 上传前后双重格式验证。
- 批量上传进度和单文件状态。
- 原文件进入对象存储。
- 异步简历解析，展示排队、解析中、成功、失败和重试。
- 结构化结果至少包含基本信息、教育、履历、技能、项目和其他招聘相关信息。
- 默认脱敏展示姓名、联系方式。
- 人才列表、筛选、详情、原文件授权下载、关联匹配和面试题结果。

OCR、候选人自动去重及合并规则需在开发前确认最低实现范围。

### 3.6 简历筛选

- 选择一个确认的 JD 版本。
- 选择一个或多个解析成功的候选人。
- AI 生成筛选方案：评估项、权重、说明、必须项、排除项和缺失信息规则。
- 用户编辑并确认筛选方案。
- 展示候选人数和用户费用预估，用户确认后执行。
- 异步显示总进度和候选人级状态。
- 允许部分成功，成功结果不因其他候选人失败而丢失。
- 输出分数、等级、匹配点、不匹配点、可协商项、缺失信息、风险、证据和人工复核建议。
- 结果绑定 JD 版本、简历解析版本、筛选方案版本和 AI 生成元数据。

AI 不得自动淘汰、拒绝或做最终录用决策。

### 3.7 AI 面试出题

- 从筛选结果明确选择候选人。
- 展示生成数量和费用预估，确认后执行。
- 根据 JD、候选人经历、匹配点、风险和待验证项生成题目。
- 输出专业、行为、场景、追问等分组。
- 每题包含出题原因、考察点、建议追问和评分要点。
- 结果保存为面试题包并关联职位版本和候选人。
- 从招聘任务、职位详情和候选人详情回看。

不按照“评分 90 分以上自动生成”执行，避免无确认的费用和决策自动化。

### 3.8 任务/对话历史

- 保存产品可见的招聘任务、消息和结构化结果引用。
- 最近任务列表、Agent/能力类型、时间、状态和用户消费。
- 只读回看和继续处理。
- 删除策略在数据保留规则确认前默认使用软删除/隐藏，不永久清除底层审计数据。

完整搜索、分类管理进入后续阶段。

### 3.9 试用额度与账单

- 新用户试用额度。
- 顶部余额显示试用额度与其他额度的合计及构成。
- 每次收费动作执行前显示估算。
- 支持预占、最终结算、失败释放和补偿。
- 消费流水显示业务能力、数量、单价、金额、状态和关联任务。
- AI Platform 上报供应商用量，但不直接扣用户余额。

在线充值、发票和优惠活动进入 P1。

### 3.10 设置与安全

- 个人头像、昵称和注册手机号展示。
- 基础通知偏好可先保存，不要求完成短信/邮件通知系统。
- 候选人 PII 默认脱敏。
- 敏感信息查看、原简历下载和删除动作服务端鉴权并审计。
- 基础账号退出。

完整 API 密钥管理、数据导出任务和高级安全设置进入 P1。

## 4. P1/P2 边界

### P1

- 完整 AI 招聘自动工作流。
- 完整面试题库管理。
- 团队邀请、角色、共享/独立额度。
- 在线充值、发票、CSV/批量数据导出。
- 微信登录和通知中心。
- 数据安全管理页、API 密钥管理。
- 帮助中心、教程和工单。
- 职位发布。

### P2

- 语音输入。
- 移动端产品。
- ATS/HRIS 和招聘渠道深度集成。
- 勋章和成长体系。
- 更复杂的自动化审批与企业 SSO。

## 6. P0 Definition of Done

- 核心闭环在 Mock AI Platform 下端到端可用。
- 页面刷新和短时网络中断不会丢失长任务。
- 业务数据、AI 结果和费用记录可追溯到同一招聘任务。
- 跨组织访问、未授权 PII 查看和重复扣费测试通过。
- AI 结果有结构、有证据、有版本、有人工确认提示。
- 真实 AI Platform 可以逐项替换 Mock，而不修改招聘领域逻辑。
