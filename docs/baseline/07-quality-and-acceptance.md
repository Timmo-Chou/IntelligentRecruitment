# 质量、安全与验收基线

## 1. 第一阶段质量目标

产品在接入真实简历前，必须证明：

- 企业数据不会跨租户访问。
- 候选人信息默认受保护。
- AI 推荐有结构、有证据、可人工复核。
- 长任务不会因刷新、重复请求或乱序回调损坏。
- 客户费用不会重复扣减且能够对账。
- Mock 可被伙伴真实 AI Platform 逐项替换。

## 2. 隐私与多租户

### 必须满足

- 所有招聘资源由服务端按 `workspace_id` 授权；企业资源同时校验一致的 `company_id`。
- 嵌套资源、搜索、数量、文件下载和回调映射同样隔离。
- 候选人姓名和联系方式默认脱敏。
- PII Reveal、原文件下载、导出和删除进入审计日志。
- PII 不进入 URL、浏览器持久化、前端埋点、错误监控和测试快照。
- 日志不包含简历正文、完整联系方式、签名 URL、密钥和敏感 Prompt。
- 发送 AI Platform 的数据遵循最小必要原则。

### 阻断发布

- 任意跨组织读取或修改。
- 未授权查看完整候选人身份或原简历。
- 伙伴平台不能说明候选人数据保留、删除或地域处理方式。

## 3. 招聘公平性与可解释性

- 性别、年龄、婚育、民族、宗教等敏感属性不得作为默认排名或排除条件。
- 缺失信息不得默认判定“不合格”。
- 每个筛选结果必须包含证据、缺失信息和人工复核建议。
- 结果保存输入版本、Prompt 版本和模型族摘要。
- UI 禁止使用“AI 自动淘汰”“系统认定不合格”等最终裁决语言。
- 用户能够看到并修改 AI 建议的筛选方案。

阻断发布：无法解释的分数、丢失版本绑定、敏感属性默认参与评分。

## 4. 文件安全

- 客户端预校验，服务端验证扩展名、MIME、Magic Bytes、大小和批量数。
- 文件进入解析前通过恶意文件扫描。
- Object Key 不使用姓名、手机号或原文件名直接拼接。
- 签名 URL 短效且每次服务端鉴权。
- 批量上传支持项目级成功/失败。
- 删除/保留策略覆盖原文件、解析结果、派生数据和伙伴副本。

阻断发布：可执行/已知恶意文件被当作简历处理，或可猜测/未授权下载原文件。

## 5. 异步任务可靠性

必须覆盖：

- 创建请求重复。
- AI Platform 接收前/后的网络超时。
- 重复回调。
- 回调乱序。
- 取消与完成竞态。
- 任务完成后迟到的进度。
- 单个候选人失败和整体部分成功。
- 重试只处理失败项目。
- 页面刷新、浏览器重启和短时断网后的恢复。
- 非法 AI Schema。

阻断发布：需要人工改数据库才能恢复任务，或重复回调产生重复结果/结算。

## 6. 计费正确性

必须证明：

- 双击确认/重复 HTTP 请求不重复预占。
- 重复完成回调不重复结算。
- 失败、取消和部分成功按照已确认政策释放/结算。
- 账本流水只追加，补偿可追踪。
- 钱包投影可与账本对账。
- AI Platform Usage 不直接修改用户余额。
- 金额不存在浮点误差。

阻断发布：重复扣费、余额无法由账本解释、供应商 Usage 直接当作客户价格。

## 7. 契约质量

- OpenAPI/JSON Schema 进入版本控制。
- Mock 和真实 Adapter 运行相同契约测试。
- 请求、响应、流事件、回调、错误和 Usage 全部校验。
- 不兼容修改提升版本并声明弃用周期。
- 伙伴特有 DTO 不进入业务领域层。

阻断发布：真实平台无法通过 P0 能力契约测试。

## 8. 测试分层

| 测试 | 内容 |
|---|---|
| 单元 | 状态机、权重、价格、账本、权限策略、Schema |
| 前端组件 | 表单、状态、可访问性、脱敏、部分失败 |
| API 集成 | 鉴权、租户隔离、事务、文件访问、幂等 |
| Worker | 重试、Outbox、回调、竞态和部分成功 |
| AI Contract | Mock/真实 Platform 请求响应和事件 |
| E2E | P0 完整闭环和异常恢复 |

## 9. P0 E2E 验收场景

### 正常闭环

```text
注册
→ 试用额度到账
→ 创建招聘任务
→ 生成/确认 JD
→ 上传并解析多份简历
→ 确认筛选方案和费用
→ 查看可解释结果
→ 选择候选人生成面试题
→ 查看任务历史和账单流水
```

### 必测异常

- 一份简历格式错误。
- 一份简历解析失败，其余成功。
- 筛选过程中刷新页面。
- 筛选部分成功。
- AI 超时后重试。
- 重复点击付费确认。
- 回调重复/乱序。
- 余额不足。
- 无权访问其他组织职位、候选人、文件和账单。

## 10. 性能目标草案

以下为评审起点，伙伴确认后冻结：

| 指标 | 初始目标 |
|---|---|
| 普通业务 API P95 | < 500ms（不含文件和 AI） |
| JD 首个流式内容 | < 3s |
| JD 完整结果 | < 30s |
| 单份普通文本简历解析 | < 30s |
| 任务创建响应 | < 2s |
| 任务进度可见延迟 | < 5s |
| 简历解析成功率 | ≥95%，按格式单独统计 |
| 重复请求/回调 | 0 次重复业务结果和扣费 |

性能结果需区分我方耗时、队列等待和伙伴执行耗时。

## 11. 可观测性验收

- 一个用户操作可以通过 ID 串联 Web 请求、业务任务、AI 任务和账本流水。
- 可查询失败发生在上传、业务服务、队列、AI Platform 或供应商的哪个阶段。
- 有队列积压、持续 AI 失败、回调验签失败、账本对账失败和存储异常告警。
- 日志和 Trace 经抽查不包含受限敏感数据。

## 12. 上线门槛

上线前需满足：

- 所有阻断级安全和计费问题关闭。
- P0 正常闭环和必测异常通过。
- 迁移、备份、恢复和回滚方案验证。
- 隐私政策、用户协议和候选人数据处理规则已由业务/法务确认。
- 伙伴真实平台接入时，通过契约、压力、故障和数据处理评审。
