# 双方职责与系统边界

## 1. 分工结论

当前分工合理，前提是采用契约优先和清晰的数据所有权：

```text
我方
① Web 客户端
② AI 招聘业务服务

伙伴
③ AI Platform / AI Gateway
④ 能力接入层
⑤ 能力供应方
```

## 2. 我方职责

### 2.1 Web 客户端

- 用户认证界面、全局框架和导航。
- 招聘工作台、结构化成果和 AI 对话展示。
- JD 编辑确认、简历上传、筛选方案确认、结果和面试题展示。
- 职位库、人才库、任务历史、余额账单和设置。
- 文件上传交互、流式内容、异步任务状态和恢复。
- 权限、隐私、错误、空状态、部分成功和可访问性体验。

客户端只调用 AI 招聘业务服务。

### 2.2 AI 招聘业务服务

- 用户、企业、成员和业务权限。
- 职位、JD 版本、候选人、简历文件和解析版本。
- 招聘任务、产品会话和消息。
- 筛选方案、运行、结果和面试题包。
- 文件授权、对象存储引用和数据生命周期。
- 用户费用预估、预占、结算、释放和账本。
- 调用 AI Platform、校验结构化结果并写入业务数据。
- 异步业务状态、幂等、Outbox、审计和监控。
- Mock AI Platform Adapter 和真实 HTTP Adapter。

## 3. 伙伴职责

### 3.1 AI Platform / AI Gateway

- 统一 AI 能力 API。
- Agent、Workflow、Skill、Prompt 和 Tool 的执行。
- 模型路由、重试、降级、流式输出。
- AI 任务状态和供应商调用 Trace。
- Token、第三方调用量和供应商成本统计。
- AI 输出的模型侧安全、格式化和技术质量。

### 3.2 能力接入层

- LLM Gateway。
- MCP Client/Connector。
- HTTP API Provider Adapter。
- 自研能力 Adapter。
- 供应商鉴权和密钥管理。

### 3.3 能力供应方

- 聘才猫、倍罗等招聘能力。
- LLM 模型。
- 伙伴自研 AI 能力。

## 4. 数据所有权

| 数据/能力 | 事实源 | 说明 |
|---|---|---|
| 用户、企业、成员、角色 | 业务服务 | AI Platform 只接收可信调用上下文 |
| 职位和 JD 版本 | 业务服务 | AI 只生成草稿或建议 |
| 候选人和简历文件 | 业务服务 | 原文件不由伙伴长期持有，除非另有协议 |
| 简历解析业务版本 | 业务服务 | AI Platform 生成，业务服务校验后落库 |
| 招聘任务和产品会话 | 业务服务 | 用户可见的历史由我方保存 |
| 筛选方案和结果 | 业务服务 | 绑定不可变输入版本 |
| 面试题包 | 业务服务 | AI Platform 返回结构化结果 |
| 客户余额、价格和账本 | 业务服务 | 伙伴不可直接修改 |
| AI 任务、Prompt、模型、Tool Trace | AI Platform | 业务侧保存必要映射和摘要 |
| Token、供应商调用量和成本 | AI Platform | 上报业务侧用于统计和对账 |
| 产品单价和客户应付金额 | 业务服务 | 与供应商成本解耦 |

## 5. 调用路径

允许：

```text
Web → 业务服务 → AI Platform → 外部/自研能力
```

禁止：

```text
Web → AI Platform
Web → 模型/第三方 API
AI Platform → 直接写业务数据库
AI Platform → 直接扣客户余额
```

## 6. 工作流编排边界

### 业务服务负责

- 用户是否确认 JD、筛选方案、候选人和预算。
- 哪个业务状态可以进入下一步。
- 结果是否写入正式业务记录。
- 用户权限、余额和计费。
- 暂停、取消和重试在产品中的业务语义。

### AI Platform 负责

- 一次 AI 能力内部调用哪些模型、Skill、Tool 或供应商。
- 模型级重试、降级和路由。
- AI 执行 Trace、供应商用量和技术错误。

完整招聘自动工作流进入 P1 后仍按此分层：业务流程由我方控制，AI 执行编排由伙伴控制。

## 7. 文件边界

- 原始简历由我方对象存储持有。
- 业务服务完成授权后向 AI Platform 提供短效文件引用或受控读取接口。
- 文件引用必须有过期时间、用途和组织范围。
- AI Platform 不得将文件引用写入日志。
- 伙伴需声明临时文件和派生数据的保留期、删除流程和数据地域。

## 8. 安全与权限边界

- 业务服务负责最终用户鉴权、组织隔离和 PII 展示权限。
- AI Platform 只信任服务间认证，不接收客户端 Token 作为最终授权依据。
- 业务服务在发送数据前根据供应商和用途执行数据最小化/脱敏。
- AI Platform 按契约执行模型侧内容安全和数据处理策略。
- 双方使用 `request_id`、`trace_id`、`business_task_id`、`ai_task_id` 关联审计。

## 9. 第一阶段合作方式

1. 我方先发布契约评审稿和 Mock。
2. 伙伴确认能力可实现性、字段、状态、限制和 SLA。
3. 双方冻结 V1 Contract。
4. 我方基于 Mock 完成 P0。
5. 伙伴按合同开发真实 Platform。
6. 用契约测试逐个替换 Mock 能力。
7. 任何不兼容调整通过版本升级，不以口头约定覆盖。
