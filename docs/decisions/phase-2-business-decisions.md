# Phase 2 业务决策记录

版本：V0.1  
确认日期：2026-08-21  
状态：由《Phase 2 注册登录、授权、租户权限与数据隔离方案》V1.0 补充并部分取代

> 最新身份、企业、工作空间和额度边界以 `docs/architecture/phase-2-identity-tenancy-and-isolation.md` 为准。本文件保留已确认的 Token 生命周期、90天有效期及不可变账本原则。

## 1. 认证

- 登录方式：手机号验证码。
- Phase 2 使用 Mock 验证码，短信能力通过可替换接口预留。
- Access Token 有效期 30 分钟，仅保存在客户端内存。
- Refresh Token 有效期 14 天，存放于 `HttpOnly` Cookie；生产环境启用 `Secure` 和适当的 `SameSite` 策略。
- 允许多设备登录，支持单设备退出和全部设备退出。
- Phase 2 不实现微信、企业微信、钉钉和 SSO。

## 2. 组织、管理员和角色

- 用户账号不区分永久的个人/企业类型；同一用户可拥有个人空间并加入多个企业工作空间。
- 企业通过统一社会信用代码和平台审核创建或认领；部门独立接入时可以仅成为 `WORKSPACE_OWNER`，不会自动成为企业 Owner。
- `Workspace` 是招聘数据和权限租户边界；企业和工作空间分别维护成员角色。
- 不设置统一管理/空间隔离两种模式；Company Owner/Admin 未加入目标 Workspace 时不得查看其中的招聘业务数据。
- MVP 不设计 Workspace 下的 Department 层级；Workspace 直接作为部门、业务线、猎头行业组或招聘团队使用。
- 每个用户最多创建一个个人 Workspace；只有 Company Owner/Admin 能创建企业 Workspace。
- 支持企业与工作空间两级邀请；未受邀用户主动申请加入企业时由平台审批，MVP 不开放 Workspace 自助申请。
- 企业业务数据强制保存一致的 `company_id + workspace_id`，个人 Workspace 数据的 `company_id` 为空。
- 手机号注册不需要平台邀请码；邀请仅用于加入已有企业或 Workspace。

## 3. 试用额度和账本

- 个人实名认证后仅发放一次30元试用额度；企业认证并创建首个工作空间后仅发放一次100元试用额度。
- 试用额度自发放时刻起 90 天过期；服务端以 UTC 保存精确的 `expires_at`。
- 个人试用额度发放到唯一的个人工作空间；企业试用额度发放到首个企业 Workspace。金额统一以人民币“分”的整数存储。
- Phase 2 建立不可变账本、冻结、结算、释放和人工调整能力，不接入真实支付。
- 余额不足时不能发起收费 AI 任务。
- 任务失败释放冻结额度；部分成功只结算成功业务单位；差额释放回原扣款账户。
- 消费时优先扣减最早到期的可用额度批次。
- 额度过期后不得再用于新任务；已经成功预占的任务不因执行期间额度到期而中断，结算完成后释放的未使用部分仍按原到期时间处理。
- 前端应展示到期日，并在临近到期时提供非干扰式提醒。

## 4. 到期规则验收口径

- 同一实名个人只能获得一笔个人初始试用金；同一认证 Company 只能获得一笔企业初始试用金。
- 发放时间与过期时间相差精确 90 天，统一按 UTC 计算和存储。
- 到期处理必须通过账本记录或可审计的额度批次状态体现，不允许只修改余额汇总值。
- 到期前创建但尚未成功预占的收费任务，应重新校验可用余额。
- 到期、预占、结算与释放必须保持幂等，并能关联原始业务引用。
